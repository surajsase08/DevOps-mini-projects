## 🎯 1. Project Objectives

The primary objective of this mini-project is to translate abstract business requirements into a structured, production-ready Agile project plan for a **Student Record and Academic Management Platform**.

Key goals include:

- **Centralizing Academic Operations:** Streamlining student registration, course management, attendance tracking, and performance reporting into a single scalable web application.
- **Adopting Agile Methodologies:** Implementing Scrum principles, managing Product and Sprint Backlogs, writing structured User Stories, and defining Acceptance Criteria.
- **Fostering Collaboration:** Assigning clear Scrum roles (Product Owner, Scrum Master, and Development Team) and conducting simulated Agile ceremonies.

## 🔄 3. Workflow Explanation

The project follows an iterative and incremental Scrum workflow divided into structured phases:

1. **Product Discovery & Vision Alignment:** Review business requirements, functional and non-functional constraints, and define measurable success targets (e.g., page load under 2 seconds and secure authentication).
2. **Backlog Grooming & Prioritization:** Decompose the platform into seven core **Epics**: Student Management, Course Management, Attendance, Performance, Security, Notifications, and Reporting.
3. **Estimation & Planning Poker:** Estimate story-point complexity using a Fibonacci scale (1 to 13) and prioritize items based on business value and technical dependencies.
4. **Sprint Execution:** Distribute work across fixed two-week sprints:
   - **Sprint 1:** Authentication, user registration, and database setup.
   - **Sprint 2:** Student Management Module (Add, Search, Update, Delete).
   - **Sprint 3:** Course Registration and Attendance Tracking.
5. **Scrum Ceremonies & Retrospectives:** Conduct daily stand-ups, Sprint Reviews, and Start/Stop/Continue retrospectives to evaluate velocity and improve processes.

## 💻 4. How to View and Use the Word Document

Since the project report is structured for official academic submission, follow these steps to view or edit the `.docx` file on your local machine:

1. **Locate or Create the File:**
   - Open Microsoft Word, Google Docs, or LibreOffice Writer.
2. **Paste the Report Content:**
   - Copy the formatted mini-project text provided in your project repository or workspace.
   - Paste it into a blank document.
3. **Apply Professional Styles:**
   - Set main titles to **Heading 1** and section headers to **Heading 2** to create a clean document structure and generate a table of contents.
4. **Insert Visual Diagrams:**
   - Use [Mermaid Live](https://mermaid.live) to render the Scrum Team and Kanban Board diagrams provided in the repository. Download them as PNG images and insert them into the Word document.
5. **Save and Export:**
   - Save the file as `Unit-2-Agile-Mini-Project.docx` and submit it to your college portal.

## 👥 5. Team Roles & Scrum Structure

- **Product Owner:** Defines requirements, prioritizes the Product Backlog, and accepts completed deliverables.
- **Scrum Master:** Facilitates daily stand-ups, removes blockers, and helps ensure Scrum is followed.
- **Development Team:** Handles system design, coding, unit testing, and feature demonstrations.
