# Unit 1 — Design Thinking and Product Planning

## Overview

Unit 1 focuses on understanding a real user problem and planning a software product before moving into implementation. The project documentation uses a student record and academic management platform as its working example.

The goal is to explain the problem, identify users and stakeholders, define requirements, plan a minimum viable product (MVP), and document an initial solution design.

> **Note:** This README summarizes the accompanying Word document. Confirm that the project topic matches the topic assigned by the instructor before final submission.

## Objectives

- Understand the problem and the needs of the people who may use the system.
- Identify stakeholders and prepare example user personas.
- Apply the Design Thinking stages: Empathize, Define, Ideate, Prototype, and Test.
- Document business needs and functional and non-functional requirements.
- Define the product vision, MVP scope, success criteria, and roadmap.
- Prepare an initial system architecture and workflow.
- Organize project documentation and maintain it in GitHub.

## Workflow Explanation

The workflow below describes the intended planning process. It is a project workflow, not proof that every activity has already been performed.

1. **Understand the problem:** Identify the academic-record management problem, the people affected, and the current difficulties. Use actual stakeholder feedback if it is collected.
2. **Define the problem:** Turn the observations and known needs into a clear problem statement and project scope.
3. **Develop ideas:** Consider possible features and compare them against user needs, feasibility, and project time.
4. **Plan the product:** Write the product vision, BRD, FRS, NFRS, MVP scope, success criteria, and roadmap.
5. **Design the solution:** Create an initial architecture and workflow showing how a user interacts with the proposed system.
6. **Review and improve:** Check the documentation against the assignment requirements, identify missing evidence, and revise the plan. If prototype testing or interviews have not taken place, record them as future work rather than completed activities.

### Workflow at a glance

`Understand problem → Define requirements → Develop ideas → Plan MVP → Design solution → Review and improve`
